# smart-crm-admin-web

CRM 管理台（独立前端仓）：商业承诺与履约协调的页面入口，供销售、主管与履约排障使用。

## 形态

- Vue 3 + Vite + TypeScript；qiankun 子应用（独立运行亦可用），base `/app/crm/`。
- 认证：浏览器 PKCE 人员令牌（IAM），令牌不跨服务转发；CRM Server API 经代理 `/api` 访问。
- 页面：工作台（客户→商机→报价→订单→履约计数）、客户列表与联系人详情、商机列表（阶段推进与输单原因）、商品目录（三态）、报价编辑器（草稿编辑→签发→确认成交，含商机关联、撤回/重议入口）、订单列表与详情、交付项、审计记录、承接方登记。

商机是独立销售聚合，必须先挂在已建档客户上；阶段按 `new → qualified → proposal → negotiation` 推进，输单必须填写原因，赢单由关联报价确认成交事务自动派生。报价也可以不关联商机，以兼容直接报价场景。

订单记录客户的商业承诺；交付按执行任务独立展示，分别使用「订单」和「交付」菜单。交付项保留交付编号及关联订单行，可从订单详情查看本单任务。失败交付项可经确认重置为待执行，保留回报序号水位；重置失败沿用同一幂等命令重试，成功后自动回读业务事实。

交付结果由承接服务回填，管理台以通用摘要展示并提供完整结果抽屉：JSON 格式化显示全部字段，其他文本按原文显示，不按某个承接服务的业务字段裁剪；未回填结果明确标识。订单可见而关联商品目录无权访问时，保留订单金额、行明细与冻结履约义务，以不可见标签代替商品名称；关联目录的网络故障仍显示可重试错误。

管理台列表统一使用服务端页码查询：请求携带 `page` 与 `pageSize`，响应必须包含 `items`、`page`、`pageSize`、`total` 四个字段。页面分页总数以服务端 `total` 为准；查询、换页和换页大小失败时保留原页面并可按原查询条件重试。机器消费者仍使用服务端游标接口，页码参数不会与游标参数混用。

## 开发

```bash
pnpm install
pnpm check      # 类型检查 + lint + 单测 + 构建
```

复制 `.env.example` 为不入库的 `.env.local`，注入实际 PKCE 公共客户端标识。生产验收使用构建产物，经 Nginx 挂载到正式 Portal；`pnpm dev` 仅用于本地诊断，需要另设置 `CRM_DEV_API_TARGET` 为诊断宿主地址，不作为 Portal 验收入口。

## 可信应用接入

IAM 侧注册值、三权登记、宿主网关与完整验收见 [docs/TRUSTED_APPLICATION_ONBOARDING.md](docs/TRUSTED_APPLICATION_ONBOARDING.md)。

## 边界

- 浏览器不接触数据库与基础设施凭据；全部数据经 CRM Server REST API。
- 页面可见性、接口操作权限与数据范围各自校验；列表按当前身份获准的数据范围读取，跨归属写入不会因列表可见而自动放开。
- 机器消费方（如 license 服务）不经过本 Web，走 OpenAPI + AKSK 客户端五件套，按运行线选择传输适配器。
